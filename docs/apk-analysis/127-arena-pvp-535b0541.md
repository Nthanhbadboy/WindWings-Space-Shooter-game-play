## 2. Cách decode (để kiểm lại được)

1. `tools/recovery/arena_pvp_native.py` mở **XAPK gốc** (assert SHA), lấy `libil2cpp.so` (assert SHA), cắt **đúng** khoảng `[offset, offset_kế_tiếp)` của từng method từ `dump.cs`, disassemble bằng capstone, và lưu: instruction + **byte literal pool thật** + **metadata slot** (địa chỉ slot + addend RELA) + **blob của `InitializeArray`**.
2. `tools/verify/arena_pvp_initializers.py` là **pass tham chiếu** (không chạy mã): nó mô hình hoá đúng vài idiom của compiler (`object_new`, `array_new`, `InitializeArray`, `List<T>.Add` bản inline, gán field, gán static). Gặp opcode lạ ⇒ **raise**, không đoán. `List.Add` có 2 đường (fast path inline và slow path `bl`) cùng **một** hiệu ứng ⇒ pass đi theo fast path và nhảy qua slow path.
3. `tools/verify/arena_pvp.py` dựng artifact. `tests/test_arena_pvp.py` (30 test) **đo lại** từng khẳng định của báo cáo từ byte gốc.

> Hệ quả phương pháp: bảng nào không dựng được trọn vẹn thì ghi **`not_decoded`** trong artifact (§9) — không có số "điền tay".

### 6.6 Mã hoá điểm `ToPoints` / `DataFromPoints`

```

```
`DataFromPoints(points)` RVA **19.871.992** (magic chia 100 / 100.000 / 1.000.000):
```

pvpStars @0x20 = (points % 100.000) / 10.000
```

**Bất đối xứng thật:** `ToPoints` clamp `point` tới **100**, nhưng `DataFromPoints` chỉ giữ `points % 100` ⇒ `point=100` **không** round-trip (thành 0). Test `PointsCodecContract` khoá cả hai chiều; clone phải chọn 99 hoặc chấp nhận mất 100.
