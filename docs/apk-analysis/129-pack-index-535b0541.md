## 2. Index → field: bảng nhảy 27 nhánh (`GetValueByIndex`, RVA **20.202.072**, 380 B)

```
cmp w1, #0x1a ; b.hi → return 0
adrp x9, #0x779000 ; add x9, x9, #0xefa      ; bảng byte
ldrb w11, [x9, x8] ; adr x10, #0x1344280 ; add x10, x10, w11, lsl #2 ; br x10
<landing pad i>: ldr w0, [x0, #(0x10 + 4*i)]
```

Không thể suy bảng từ thứ tự instruction (bảng hoán vị sẽ trông y hệt), nên **bytes bảng được pin**: VA **7.839.482** (0x779EFA), 27 byte `0005080b0e1114171a1d202326292c2f3235383b…`, và mỗi entry được kiểm ngược: `target = 0x1344280 + 4*entry` phải là landing pad nạp `[x0, #0x10+4i]`. Kết quả: **27/27 khớp, entry tăng đơn điệu** ⇒ index tuyến tính đúng như đọc ban đầu, và `multipleBonus (0x7C)` **không có index** (index 26 dừng ở `Premium 0x78`).

## 4. Quy đổi energy → gem (`Board_ShopEnergy`, RVA gốc **19.432.384**, 168 B)

```
if (!GameDatas.IsProVersion()) return -1;
w8 = 0x1e (30);  w9 = 0x51EB851F;  x8 = smull(w8 * _energy, w9)
x9 = x8 >>> 63 ; x8 = x8 >>asr 36 ; return (w8 + w9)
```

Đó là phép chia có dấu cho 100 bằng magic constant (`0x51EB851F`, shift 36, hiệu chỉnh bit dấu), nhân trước với 30:

> **GetExchangeGemsFromEnergy(e) = (e × 30) / 100 = 0,3 gem/energy, cắt phần nguyên; = −1 nếu không phải Pro.**

Kiểm: 20→6 · 50→15 · 100→30 · 1→0 · 3→0 · 0→0.

Kinh tế energy quanh đó (`Board_ShopEnergy`): `GetCostBuyEnergy()` = **30**, `GetValueBuyEnergy()` = **50** (mua 50 energy giá 30 gem ⇒ 0,6 gem/energy, tức mua rẻ hơn quy đổi 0,3), `GetValueFreeEnergy()` = **30**. `.cctor` chỉ ghi `backBoard` từ literal 8 B `00000000 01000000`.
